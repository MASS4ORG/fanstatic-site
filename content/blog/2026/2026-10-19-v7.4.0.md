You write `[[coffee]]` in your notes, not a URL. v7.4.0 brings that habit to Fanstatic: wikilinks resolve to pages and taxonomy terms at build time, so links survive slug changes and content moves.

* [What a wikilink resolves to](#what-a-wikilink-resolves-to)
* [Missing targets](#missing-targets)

## What a wikilink resolves to

A wikilink is `[[target]]` or `[[target|label]]`. The target is a content path (`posts/my-post.md`, `/posts/my-post.md`) resolved exactly like [`ref`](/docs/content/shortcodes), a taxonomy term (`tags/coffee`), or a bare name that tries a term first and then a page:

```md
Read [[posts/how-to-brew.md]] next, or browse everything tagged [[tags/coffee]].

The [[coffee|bean]] is a seed, not a bean.
```

Bare targets prefer a taxonomy term, so `[[coffee]]` links to the `coffee` tag when one exists. The calling page's language and output format are the defaults, matching `ref`, so a wikilink in a Portuguese page points at the Portuguese translation. The label after the pipe is optional.

Wikilinks also work in shortcode Markdown and the `markdownify` template filter. In a Markdown table, escape the label separator as `[[coffee\|bean]]`. Plain text and image descriptions use just the display label.

## Missing targets

A target that resolves to nothing renders a link to `./` and logs an error, and the build keeps going, so a typo never blocks a deploy. When you would rather catch it early, turn it into a hard failure:

```yaml
MissingWikiLinkAsError: true
```

See the [wikilinks guide](/docs/content/wikilinks) for the full resolution rules.
